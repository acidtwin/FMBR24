## 1. What this is, run, test

PyQt6 desktop tool (Linux, Python 3.12) that parses FM24 saves (`.fm`, FMF archive, zstd members): clubs, squads, staff, scouting reports, shortlists, Save Info, a detailed player window, plus homegrown (HGP/HGC) patching. Unofficial, never imply affiliation with Sports Interactive / SEGA (README, About dialog, `fm_editor/settings.py::LEGAL_LINE`). FM24 only (FM23 saves fail in `archive.py`).

```bash
pip install -r requirements.txt        # PyQt6, zstandard, numpy
python main.py                         # crash log /tmp/fm_editor_debug.log
FMBR24_CONFIG_DIR=$(mktemp -d) QT_QPA_PLATFORM=offscreen python3 tests/test_<name>.py   # plain scripts, no pytest
```

- Always set `FMBR24_CONFIG_DIR` so `~/.config/fm24_editor/settings.json` is untouched. Cache `~/.cache/fm24_editor` and config dir keep the old app name on purpose.
- 38 `tests/test_*.py` plus `tests/snapshot.py` (helper) and `tests/golden_parse.json`. Real-save tests print `SKIPPED ...` and exit 0 when the save is absent: `test_parse_golden` (~40 s reported), `test_squads` (~30 s), `test_saveinfo`, `test_injuries`, `test_human_clubs` (real part), `test_club_extra`, `test_player_stats`, `test_club_info`, `test_contract_block`, `test_height_weight`, `test_value_est`, `test_history` (also needs the FM install DB). `test_traits`/`test_potential` skip their real-player part without a scratchpad pickle. The rest are synthetic.
- **Snapshot-gated** (`test_club_extra`, `test_player_stats`): in-game values move as the user plays; `tests/snapshot.py` runs exact checks only at `SNAPSHOT_DATE = 2028-01-02` (budget also needs the recorded game name), else "INVARIANTS ONLY". `FMBR24_SNAPSHOT_SAVE=<frozen copy>` forces exact.
- **Golden** (`test_parse_golden`): hashes offset-INDEPENDENT fields only, so a re-save (HGC/HGP insert shifts offsets) does not break it. Re-baseline (delete the json, rerun) only after a deliberate parser change. `FMBR24_GOLDEN_SAVE=<path>` for another copy.
- Headless UI check and mockup rules: `CLAUDE.md`.
- README screenshots: `scripts/make_screenshots.py <save>` (or `FMBR24_SAVE`) regenerates every PNG in `docs/screenshots/` offscreen from a real save (fresh parse, manager name masked, one queued HGP shown in memory, nothing saved); add a shot = one function in its `SHOTS` dict.

## 4. Save and patch system (HGP / HGC)

HGP = secondary-nation record `b10=0x08,b11=0x46`; HGC = training record `b10=0x01,b11=0x48`, bytes 0-3 = club entity id = club id + 1. `MainWindow._entity_of` is the ONE helper for display and write (`patch.find_club_entity_id` is a vote that disagrees for ~1,800 clubs; unused by the GUI). Record scans cover the full record count (up to 125 per player). Layouts: memory file.

1. **Controls:** HGP/HGC pills in the player window header (`queue_toggle`); Squads toolbar `Make HGP`/`Make HGC` (`_queue_selected`, `_update_patch_btns`). Only players of a human-managed club (`save_data['human_clubs']`) are queueable; others get a display-only pill. A player with no club shows no HGC pill.
2. **Queue** = `MainWindow._queue`, `(person id, 'hgp'|'hgc') -> person` (nothing patches `game_db` in memory). `_queue_changed` sets `_dirty`, status, 'Unsaved changes', enables Save, refreshes badges and the open player window. Cleared by Load/Reload/`_finish_load` and after a successful save.
3. **Save Changes** (`_do_save`): one confirm dialog (skipped on close/load-another). `_apply_queue_copy` runs `patch.apply_queue` on a COPY of the buffer (HGP in place on existing 0x46 records; inserts for persons sorted by record offset descending: an HGC record, plus a NEW England 0x46 record for a person with none). `SaveWorker` -> `savefile.save_in_place`: writes `<save>.fm.tmp`, re-opens and verifies (member list, sha256 of unmodified members, decompressed `game_db.dat` equals the patched buffer), backups, `os.replace`. Any failure leaves the original file, buffer and queue untouched.
4. `_on_save_done` clears the queue and reloads automatically (not when a close/load-another is pending). **Restore after reload:** `_capture_ui_state()` / `_apply_ui_state()` restore view, club + squad tab, search text, filters, Players subset, sort, selection, Back/Forward history. A different file, missing club or the Settings page falls back to the landing page. Not restored: open player window, queued changes, pixel scroll. Test `test_reload_restore.py`.
- **Backups:** `<save>.fm.bk1` = file before this save, `.bk2` = previous bk1; first save makes both from the original; a lone bk2 is kept as the original; failed rotation after the replace counts as saved (`info['backup_error']`). Names end `.bk1/.bk2` so FM24's Load Game ignores them. Space check 3x file size on a first save, else 2x (+16 MB). Save refused if the file changed on disk since load (`save_data['disk_sig']`). Dirty guards: Reload asks 'Discard unsaved changes?'; Load another / close ask Save / Discard / Cancel.
- **List badges:** `_HGBadgeDelegate` (Squads both; Reports and Players HGP only; Shortlists none); queued = yellow `+ HGP`; `_RowMarkDelegate` (`ROWQ_ROLE`) tints queued rows; `PeopleModel.set_queue`, `_refresh_queue_marks`.
- Tests: `test_patch_queue.py`, `test_savefile.py`, `test_hg_badges.py`, `test_human_clubs.py`.
- **Decision (2026-10-01):** patches still overwrite a player's existing 0x46 / 0x48 records (losing e.g. other-nation or previous-club records); left as is, it works in game.

- Known layout items: Profile scrolls ~136 px at the default size (ignore); GK profile has a gap under the Goalkeeping column.

## 6. Data pointers

Byte-level facts: memory `fm24-binary-format.md` (read before touching a parser). Index: s1 player record, s2 linked records, s3 staff, s4 Save Info, s5 club record, s6 finances, s7 season stats, s8 squad arrays, s9 traits, s10 reputation/stadium/league table/scouting budget, s11 height/weight/wage (a second '11' is career history), s12 contract block + wage, s13 injuries + transfer value. Dead ends and open decodes are listed there (Save Info: start nation, database size, future transfer mode, editor allowed/used, manageable teams need a second save with known different settings). Not in the save (checked): club Region/Founded/Facilities, contract bonuses/clauses, player photos (they come from the user's facepacks, see Faces), staff reputation.
